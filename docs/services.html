Services

Two, and you will mostly use neither.

energy_balancer.set_option

Change a tunable at runtime. The change is applied to the running chain immediately and written into the config entry, so the options flow, the dashboard slider and the service call never drift apart.

FieldRequiredMeaning
optionyesThe parameter to change.
valueyesA number, or an entity id to follow live.
cellnoWhich cell — or which pool. Omit for a system-wide setting.

What can be changed

ScopeOptions
Per cell (cell given) sunny_min_soc, no_sun_min_soc, hysteresis, charge_floor_w, take_pct, pv_weight, min_soc_mode, manual_min_soc
System-wide (cell omitted) peak_limit_w, observer_mode, import_price_per_kwh, export_price_per_kwh

Anything else is rejected with an error naming the options that are allowed. These are the settings that can be applied without rebuilding the chain; the rest need the options flow, because changing them means a reload.

Naming a pool

Give a pool id instead of a cell id and the value fans out to every member. That is the correct way to move a state-of-charge floor on pooled storage — writing it to one member only would leave the two halves of a pool disagreeing about where the floor is.

Examples

# Give the car charger half of what it is offered
action: energy_balancer.set_option
data:
  cell: car_charger
  option: take_pct
  value: 50

# Raise the floor on the whole battery pool before a cold night
action: energy_balancer.set_option
data:
  cell: home_battery
  option: no_sun_min_soc
  value: 60

# Follow a live entity instead of a fixed number
action: energy_balancer.set_option
data:
  cell: goodwe
  option: take_pct
  value: input_number.goodwe_take

# Back into observer mode
action: energy_balancer.set_option
data:
  option: observer_mode
  value: true

Live tunables do not trigger a reload. Changing one of these from a script every few minutes is safe; changing something else from the options flow rebuilds the chain and briefly interrupts steering.

energy_balancer.generate_dashboard

Builds a complete Energy Balancer dashboard from your actual configuration and registers it with Home Assistant. Run it once after setup, and again whenever you add or remove a cell.

FieldDefaultMeaning
dashboard_titleEnergy BalancerThe name shown in the sidebar.
dashboard_pathebi-dashboardURL path. Must contain a hyphen — Home Assistant requires it.
action: energy_balancer.generate_dashboard
data:
  dashboard_title: Energy
  dashboard_path: energy-balancer

The card bundle is copied into your www/ folder and registered as a Lovelace resource with a content hash appended, so an updated bundle is picked up without anyone having to clear a browser cache.

On a brand-new installation the dashboard may only appear after one restart — Home Assistant has to notice the new registration. After that it updates live.

Re-running the service overwrites the dashboard at that path. If you have customised it, generate to a different path or make a copy first.
