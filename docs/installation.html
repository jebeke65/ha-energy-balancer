Installation

Install, point it at three sensors, and leave observer mode on until you trust the numbers.

Before you start

You needNotes
Home Assistant 2024.6.0 or newerOlder versions lack the config-entry migration API this integration relies on.
Solar production sensor, WRequired.
House consumption sensor, WRequired. Ideally excluding the devices you plan to steer.
Grid power sensor, W, + = importRequired.
A state-of-charge sensor per battery, %Only if you have batteries.
A script per steerable deviceNot needed on day one — observer mode calls nothing.

Install via HACS

Once the repository is in the HACS default store:

  1. HACS → Integrations → search for Energy Balancer.
  2. Download, then restart Home Assistant.
  3. Settings → Devices & services → Add integration → Energy Balancer.

As a custom repository

Before it is accepted into the default store, add it by hand:

  1. HACS → ⋮ (top right) → Custom repositories.
  2. URL: https://github.com/jebeke65/ha-energy-balancer, category Integration.
  3. Add, then download it from the HACS list as usual, and restart.

Manual install

  1. Download the latest release.
  2. Copy custom_components/energy_balancer/ into your Home Assistant config/custom_components/ directory.
  3. Restart Home Assistant.
  4. Add the integration from Settings → Devices & services.

First run

1. The system screen

Point at your three required sensors. Everything else on that screen can wait — see Configuration for what each field does.

Leave observer mode on. It is on by default, and it means the integration will compute everything and touch nothing.

2. Add your cells

Add one cell per steerable device. For a first run, give each one its position, type, capacity, state-of-charge sensor and power sensor, and leave the actuator empty. See Cells.

3. Watch it for a day

Compare against what you already know:

  • sensor.eb_house against your own consumption figure.
  • sensor.eb_net against your meter — including the sign.
  • Each cell's power sensor against its vendor app.
  • sensor.eb_status for the chain's own summary.

If the grid sign is inverted, everything downstream is quietly wrong: surplus reads as deficit and the chain will try to charge when it should discharge. Check this first, and fix it in a template sensor rather than compensating elsewhere.

4. Write the actuator scripts

One script per device, taking a direction and a power figure. Everything vendor-specific belongs here and nowhere else. Fill in the actuator service on each cell once the script exists.

5. Go live

Turn off switch.eb_observer_mode. Watch the grid sensor for the next few minutes: the most common first-day fault is an actuator script that reacts in the wrong direction, and that shows up immediately as the grid swinging instead of settling.

You can turn observer mode back on at any moment, from the switch or from the options flow. The two stay in sync.

Upgrading

Config entries are migrated automatically. Two migrations exist so far: one that rewrote the cell mode vocabulary, and one that adopted entity wiring from an older YAML setup. Both are idempotent, and neither touches a number you have changed yourself — a slider you moved survives an upgrade.
